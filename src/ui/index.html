CFD Inflow & Boundary Conditions Protocol

The upstream inflow boundary is specified using an atmospheric boundary layer (ABL) profile with friction velocity \(u_* = 0.4\text{ m/s}\) and roughness length \(z_0 = 0.05\text{ m}\). Top and lateral boundaries apply zero-gradient slip conditions. Building walls and ground apply standard wall functions (\(y^+ \in [30, 200]\)). The downstream boundary enforces convective Neumann zero-gradient pressure \(p = 0\text{ Pa}\).

Dataset Provenance & Benchmark Splits

Audit of data sources, synthetic test fixtures, canonical aerodynamic benchmarks, and planned 538-layout UrbanTALES dataset integration.

1. Data Tier Breakdown

The application operates with a strict 3-tier data provenance system to guarantee scientific validity:

Tier 1: Real CFD Reference

OpenFOAM cases in cfd/cases/simple2d_building_block solved with simpleFoam. 65,408 computational cells, converged to \(10^{-5}\) residuals.

Tier 2: Analytical Benchmark Fixture

24 synthetic layouts generated via cfd/scripts/generate_canonical_reference.py implementing Castro & Robins (1977) surface-mounted obstacle wake equations and canyon channeling.

Tier 3: Planned Target Dataset

UrbanTALES 538-layout urban aerodynamic corpus (Nazarian et al. 2025). High-resolution LES slices to be ingested into pipeline.

2. Zero-Leakage Held-Out Partition Protocol

To prevent spatial data leakage, partitions are separated strictly by topological geometry families rather than random patch sampling:

  • Training Split (60%): Family A (Regular Aligned Grids) and Family B (Staggered Grid Arrays).
  • Validation Split (20%): Family C (Courtyard / Enclosed Perimeter Blocks).
  • Held-Out Test Split (20%): Family D (Asymmetric Street Canyons and High-Rise Plazas) — completely unseen building shapes and canyon aspect ratios.
